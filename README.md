# Candy W 跑团导演 v2

Candy W 是 SillyTavern 当前单角色聊天背后看不见的故事导演。剧本先确定核心事实、幕后秘密、NPC 的真实目的、事件时钟、允许的分支与结局；导演决定这一轮“发生什么”，当前聊天的 AI 保持角色卡的人设、关系和口吻，负责把场景、人物与后果演出来。玩家只生活在故事里，不维护团务表，也不会看到未来剧情。

> **当前源码状态：可提交、推送和供正常单角色聊天使用；尚未真实酒馆验收。** 导演状态严格绑定 `characterId + chatId`。SillyTavern 1.18.0 没有把主演出响应绑定回原 chat 的正式提交参数：若在 Candy W 主演出尚未结束时，经检查点、分支或其他宿主路径切到另一聊天，扩展会在可观察到切换后停止自己拥有的请求、清空注入并保留来源聊天的恢复点；但对恰好已经抵达的非流式回复，核心没有“写回原 chat”的正式接口。这个极窄竞态是已知宿主使用限制，不是源码发布阻断；生成未结束时请不要切换聊天。

v2 是完整替换实现，不是 v1 控制台的补丁，也不含 v1 兼容或迁移层。扩展版本为 `2.0.0`，旧实现只保留在 Git 历史中；v1 团务、导出文件和旧聊天 metadata 不会被 v2 读取、迁移或删除。

## 一次旅程怎样进行

1. 在 SillyTavern 中选好当前连接和模型，打开一个单独角色的聊天，并照常启用需要的世界书、persona、scenario 与 Author's Note。
2. 打开 Candy W，选择一个只展示无剧透简介的剧本。扩展自带一个可从开场完整走到结局的示例剧本，也接受通过严格 schema 校验的剧本包。
3. 写下玩家称呼、简短设定、与当前角色的关系起点，并把 `+2 / +1 / +0` 分配给身手、洞察、交涉。已有聊天会承接已经发生的关系和历史；空白聊天从剧本开场进入。
4. 点击“进入世界”。开场完成后，回到原聊天框，像平常一样自由描述行动。每次普通发送都会自动触发导演事务，不需要再点“继续剧情”。
5. 导演在幕后理解行动，依据当前剧情节点、已提交事实、隐藏变量、NPC 行动和时钟确定必须发生的内容、允许的变化与不可泄露边界；随后让当前角色把决定演出来。玩家绕路、拖延或错过钩子时仍能自由行动，但世界与幕后事件不会停下。
6. 需要判定时，演出停在结果发生之前。面板公开说明判定原因、属性、公式、难度，以及成功与失败的 stakes。玩家只投一次公开骰；骰面、修正、总点和成败立即成为不可改写的剧情事实，下一次演出自动落实对应后果。
7. 面板只显示当前场景、已知目标、认识的人与关系、已知线索和物品、可感知危机与时间、公开判定、当前章节和最终结局。这些记录来自已经提交的导演结果，不要求玩家手工整理剧情。

当前角色不会被替换成通用 KP。它仍是角色卡中的那个人，只是在导演给定的事实边界内同时演绎环境、场景 NPC、公开判定提示与后果。

## 剧本包与导演状态

剧本包有独立版本和严格 schema，包含固定核心事实、幕与场景图、隐藏秘密、NPC 目标、事件时钟、触发条件、可走分支、判定 stakes 和结局。导入会检查字段形状、引用关系、剧情图可达性、时钟和结局；不完整、未知版本、包含多余字段或引用失效的文件会被拒绝。选择剧本后，当前旅程固定一份剧本快照，之后更新同名剧本不会悄悄改写正在进行的故事。

剧本包外层固定为 `{ "format": "candy-w-rpg-director/scenario-package/v2", "exportedAt": "...", "scenario": { ... } }`；`scenario` 的权威字段、约束与交叉引用见 [`src/domain/scenario-schema.js`](src/domain/scenario-schema.js)，内置完整示例见 [`src/scenarios/fog-harbor.js`](src/scenarios/fog-harbor.js)。schema 是 exact-key：不得附加生产代码未声明的说明字段。

导演状态与玩家可见状态分离。固定核心和已提交骰果不能由演出模型改写；过程、代价、公开关系和最终结局可以沿剧本允许的分支变化。未来场景、秘密原文、隐藏变量、NPC 幕后行动和未触发结局从不进入玩家面板，也不会作为完整剧本交给主演出模型。

自由文本的理解使用 SillyTavern 当前连接提供的正式 `generateRaw()`：模型只能从导演已经允许的行动与属性 ID 中分类，并回传绑定本次 transaction/revision 的严格 JSON。它不能直接提交状态 patch、创造剧情节点或修改骰果。响应缺字段、多字段、越权引用、身份不匹配或 JSON 无效时，本次普通生成会停止并进入可恢复错误，而不会把猜测伪装成已经推进。

### 原生检查点与分支

同一剧本可以绑定多个聊天，每个聊天都是独立时间线。SillyTavern 原生创建检查点或分支后，新聊天会带着来源聊天当时的 metadata；Candy W 只在它带有原生 `main_chat` 标记、来源与目标属于同一角色且标记精确指向来源时，自动把复制的剧本快照与**已提交**导演状态重绑为新 `characterId + chatId`。之后 B 的骰果、时钟、NPC 行动和结局只推进 B，不会回写 A。

这叫“当前状态克隆”，不是“回到所点旧消息的精确历史回溯”：原生 branch/checkpoint 截取的聊天消息可以早于创建时的导演状态，而核心复制的是创建瞬间的 metadata。新时间线的运行游标和进行中事务不会继承；如果来源聊天仍有未完成的导演事务，Candy W 会拒绝接管该副本，需先完成或恢复来源聊天这一轮后再创建检查点/分支。

## 原生 SillyTavern 上下文

Candy W 不配置独立 API、不保存 Key、不绑定模型供应商，也不重新编译 SillyTavern 已经负责的上下文。每次导演理解和正式演出都沿用当前连接与模型；角色卡、当前聊天历史、已激活世界书、persona、scenario 和原生 Author's Note 仍由 SillyTavern 按自己的规则编译。Candy W 的编译器不会读取、复制或强塞这些内容，只补充本轮经过白名单投影的导演演出指令。

### World Info scan seed

v2 为每轮生成使用两个正式扩展提示槽：

- 演出指令进入普通 system prompt，`scan=false`；它只含本轮公开事实、必须发生的内容、判定结果和不含秘密原文的禁止边界。
- 当前场景已经公开的人名、地点、组织和事件锚点进入 `position=NONE`、`scan=true` 的扫描 seed；seed 本身不作为额外正文注入。

SillyTavern 再用这个 seed 扫描当前已经激活的全局、角色、聊天和 persona World Info，并继续执行原生的禁用状态、关键词/选择性触发、角色过滤、constant、概率、sticky、递归与预算规则。因此 seed 只是参与原生匹配的场景线索，不保证某条目一定激活；它不读取或复制整本世界书，不创建第二套优先级，也不绕过用户的激活设置。隐藏秘密和未来节点绝不会进入 seed。

源码核验与精确行号见 [`docs/SILLYTAVERN-1.18.0-EVIDENCE.md`](docs/SILLYTAVERN-1.18.0-EVIDENCE.md)，一页体验定义见 [`docs/EXPERIENCE.md`](docs/EXPERIENCE.md)。

## 自动事务、保存与恢复

状态按稳定的 `characterId + chatId` 隔离并保存在当前聊天 metadata；Candy W 的建团、导入与进入命令会在群聊中直接拒绝，不保存旅程、不注入提示，也不触发导演请求，而全局 interceptor 不会阻断原生群聊生成。每轮最多只有一个事务，并绑定来源用户消息、基础 revision、预期回复位置和当前聊天身份：

- 导演请求前先保存 pending transaction；并发生成或切聊不会复用它。
- 隐藏决策失败时不开始主演出；主演出失败或被停止时不提交剧情结果。
- 完整回复通过协议检查后，才确定性应用本轮结果并暂存新 metadata；SillyTavern 随后的正常聊天保存会把正式回复与导演状态写入同一聊天文件。
- 刷新后可从已保存的 pending transaction 恢复或重试；已经提交的事实不会因重试重复应用。
- 原生检查点/分支的同角色 `main_chat` clone 会显式接管为新的独立时间线；它只继承已提交的 state/scenario，重建新聊天的运行游标，绝不继承来源聊天的进行中请求。
- 观察到切聊、身份变化或流式 token 身份不匹配时，会立即通过正式 `stopGeneration()` 停止本插件拥有的请求、清空提示，并让旧聊天保留恢复点；禁用和卸载同样先停止 owned request 再拆监听。常规角色切换、历史聊天和新建聊天入口受生成锁保护；检查点、分支等路径的迟到非流式响应仍有下文明确记录的极窄宿主竞态，不能写成数学上的绝对保证。

SillyTavern 1.18.0 在 `MESSAGE_RECEIVED` 之后才判断并执行主演出的工具调用，正式扩展接口无法在提交前可靠区分工具中间回复。为避免工具递归产生一段不受导演事务约束的演出，Candy W 会在每次主演出前通过正式 `canPerformToolCalls('normal')` 检查：当前普通生成启用了工具调用时，本轮失败关闭并保留恢复点，面板会要求先关闭工具调用再重试。扩展不会替用户改设置，也不会用事件或 DOM 补丁拦工具。

“保存旅程”导出当前 v2 状态及其固定剧本快照；“继续保存的旅程”只接受严格校验且身份边界明确的 v2 文件。导入不会兼容 v1 文件，也不会把一个聊天的隐藏状态合并到另一个正在进行的旅程。

结束旅程是危险动作，需要确认；如需留档必须先导出。确认后它会清除当前聊天中的本团 v2 导演状态，并立即清空 Candy W 的提示注入。禁用扩展时，manifest 的正式 `disable` hook 会移除监听、generation interceptor、面板和本扩展的两个提示槽。它不会改写聊天正文，也不会删除用户的角色卡、世界书、聊天或其他扩展数据。

## 安装、发布与更新边界

最低目标版本为 SillyTavern `1.18.0`。v2 已完成隔离源码验证，可提交和推送；这不等于已经在用户真实酒馆安装或以真实模型验收。本 README 不把本地 fake-adapter 验证写成真实酒馆验收，也不代替用户对安装、角色卡、世界书和模型连接的确认。v1 团务与导出始终不能导入 v2。

产品范围固定为“单人玩家 + 当前一个角色聊天中的 AI 演出”。不包含多人、群聊、地图战棋、通用 VTT、独立 API、Key 管理、供应商切换，或对 SillyTavern 核心和其他扩展的修改。实现不使用 DOM/聊天输入框劫持、私自 `fetch` 生成、事件猴补丁或核心补丁来绕过正式接口。

## 已知的 1.18.0 正式接口边界

**生成期间跨聊天（已知宿主使用限制）：** 常规角色切换、历史聊天和新建聊天入口都有生成锁：角色切换在 `public/script.js:887-905` 仅于 `!is_send_press` 时执行，历史聊天入口在 `public/script.js:11532-11537` 仅于 `!is_send_press` 时打开。检查点旗标、检查点“返回主聊天”和旧消息“创建分支”则不是完整保护：带 `bookmark_link` 的旧消息旗标始终可见（`public/style.css:4495-4501`），生成态 CSS 只隐藏最后一条消息的操作（`public/style.css:4569-4575`），对应处理会直接调用 `openCharacterChat()`（`public/scripts/bookmarks.js:312-321, 449-466, 685-733`）。底层函数会先清空当前聊天、改变角色的 chat id 并载入新聊天（`public/script.js:7685-7690`），`getChat()` 在替换全局 `chat` 与 `chat_metadata` 后才发出 `CHAT_CHANGED`（`public/script.js:7594-7609, 7625-7642`）；迟到的非流式响应由 `saveReply()` 写入此刻的全局 `chat`（`public/script.js:5464-5479`），没有请求所属 chat id 的校验或扩展可用的 pre-save hook。v2 会在身份变化、流式 token 身份不符、`CHAT_CHANGED`、禁用和卸载时立即调用正式 `stopGeneration()`，但它不能倒回已经被核心写出的非流式回复。因此正常使用应等待生成结束再切换聊天；这一点被明确记录为 1.18.0 宿主限制，而非源码提交或推送阻断。

**流式事后审查：** SillyTavern 1.18.0 没有“模型已生成完整回复、但任何 token 尚未显示”的统一扩展钩子。流式 token 会立即进入 UI，所以 Candy W 不能承诺在玩家第一次看到任意流式输出前完成全文语义审查。当前设计把秘密限制在隐藏决策阶段，主演出只接收最小白名单投影，并在完整回复事件中验证协议；如果需求升级为“所有流式文本必须全文审查后才能显示”，正式 API 无法端到端满足，本扩展不会用非官方劫持伪造完成。

**磁盘 durability 确认：** SillyTavern 的聊天写入成功时使用原子文件替换，但 `saveChatConditional()` 会吞掉保存异常，扩展事件流没有独立的磁盘落盘 acknowledgement。因此 v2 能保存并恢复已经持久化的 pending transaction，也能让回复与提交状态参与同一次原生最终保存；它不能从扩展侧证明每次调用都已经 durable 地写入磁盘。

**工具调用主演出：** 1.18.0 在正式回复事件之后才识别并递归执行工具，没有“先告诉扩展这是工具中间回复”的正式 hook。v2 不伪造兼容：导演主演出要求当前普通生成关闭工具调用；启用时安全停止并保留恢复点。隐藏行动理解使用 `generateRaw()`，属于宿主禁止工具调用的 quiet/raw 路径。

这些边界不会被测试替身包装成“已解决”。当前交付以 SillyTavern 1.18.0 本机源码、fake official adapter、严格 schema/领域测试和真实生产 UI 的桌面与 `390×844` 渲染检查为验证边界，**尚未在用户真实酒馆中安装或以真实模型验收**。
